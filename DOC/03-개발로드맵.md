## 1. 진행 방식

- **현재 단계는 기획이다.** 구현은 기획 문서가 정리된 뒤 별도로 시작한다.
- 프로젝트의 목적은 **많은 사람이 플레이하는 것**이다. 그래서 만들기 전에, 그리고 만드는 도중에 실제 사람의 반응으로 방향을 확인한다.
- **재미를 먼저 검증한다.** 이 게임의 차별점인 "날씨 → 수색 → 대피·귀환" 루프만 담은 10분짜리 시제품을 가장 먼저 만들어 플레이 테스트를 한다. 전투·제작·성장은 그 결과를 본 뒤에 붙인다.
- 모든 마일스톤은 **플레이 가능한 상태**로 끝낸다.
- 시제품 단계에서는 캡슐·박스 같은 임시 도형을 쓴다. 다만 플레이어 캐릭터는 M2에서 실제 모델로 바꾸고, 소품 몇 개에 에셋을 시험 적용해 스타일을 정한다([에셋 후보](08-에셋후보.md)). 전체 교체는 수직 슬라이스 단계에서 한다.
- 대상은 데스크톱 웹 브라우저다. 코드 프로젝트는 `Src/` 폴더에 둔다.
- **싱글플레이로 먼저 만들고 멀티플레이는 수직 슬라이스 이후에 추가한다.** 그때 대규모 재작성을 피하기 위해 처음부터 [기술 설계서](02-기술설계서.md) 18장의 대비 원칙을 지킨다.
- **배포와 홍보 계획은 아직 없다.** G1 결과를 본 뒤 정한다.

```
1단계: 시제품            검증 관문        2단계: 수직 슬라이스
M0 → M1 → M2  ────────▶  G1  ────────▶  M3 → M4 → M5 → M6 → M7 → M8
(핵심 루프 10분)        (플레이 테스트)   (구역 4개, 30분 분량)
```

## 3. 1단계: 시제품

목표는 **가장 적은 작업으로 "이 게임이 재미있는가"에 답하는 것**이다. 여기서 만드는 것 중 일부는 버려도 된다.

> 이 단계의 실행 계획은 [시제품 개발 계획](05-시제품개발계획.md)에 있다. 56개 단계로 나누고 단계마다 검증 방법을 붙였다. 시제품에 무엇을 만드는지는 [시제품 설계](06-시제품설계.md)에, 화면의 배치와 흐름은 [UI 설계](07-UI설계.md)에 있다. 아래 목록은 개요이며, 두 문서가 다르면 시제품 개발 계획이 우선한다(UI 도구 도입 시점, 물리 엔진 설치 시점 등이 조정되었다).

### M0 — 기반
- [x] `Src/`에 Vite + TypeScript 프로젝트 구성
- [x] 의존성 설치 (`three`, `miniplex`, `vitest`). `@dimforge/rapier3d-compat`는 M1의 첫 단계에서 설치
- [x] 고정 타임스텝 게임 루프
- [x] ECS 월드 구성
- [x] 렌더러, 조명, 테스트용 평지, 화면 크기 대응
- [x] 입력 추상화 (키보드). 마우스 시점은 M1에서, 게임패드는 선택 단계로 미룸
- [x] 성능 HUD (FPS, 드로우콜, 삼각형 수, 구간별 시간, 프레임 그래프)
- [x] 문구 체계 (영어, 한국어)
- [ ] 프로젝트 규칙을 `CLAUDE.md`에 기록

### M1 — 캐릭터와 구역
- [ ] Rapier 초기화, 캐릭터 컨트롤러 (걷기, 달리기, 점프, 경사)
- [ ] 3인칭 카메라 (추적, 회전, 벽 충돌 보정)
- [ ] 렌더 보간
- [ ] 구역 정의 파일 형식과 로더 (지형, 건물 배치, 대피 영역)
- [ ] 임시 도형으로 "마른 강바닥" 구역 제작: 지형, 폐가 2~3채, 버려진 차량
- [ ] 캐릭터는 캡슐 또는 무료 모델 하나 (대기, 달리기 애니메이션만)

### M2 — 핵심 루프 시제품
전투, 제작, 저장, 성장은 넣지 않는다.

- [ ] 플레이어 캐릭터를 실제 모델로 교체, 소품 몇 개에 에셋 시험 적용(스타일 결정)
- [ ] 게임 시각과 날씨 상태 전환 (평상시 → 예고 → 모래폭풍 → 잦아듦)
- [ ] 모래폭풍 표현: 다가오는 폭풍의 벽, 안개, 입자, 바람 소리
- [ ] 체온과 체력 (단순판: 폭풍에 노출되면 체력 감소, 밤에는 추위)
- [ ] 대피 영역 판정 (건물 안에서는 안전)
- [ ] 컨테이너 수색과 줍기, 칸 수가 제한된 가방 (단순판)
- [ ] 물 마시기 (갈증 하나만)
- [ ] 대피소 구역과 구역 전환 (강바닥 ↔ 대피소)
- [ ] 귀환 정산: 대피소에 돌아오면 가져온 물건을 보여 주고 하루를 넘김
- [ ] 폭풍이 지나간 뒤 드러나는 물건
- [ ] **도입부 (첫 2분)**: 기획서 13장의 흐름대로 구현
- [ ] 최소한의 HUD: 체력, 체온, 갈증, 가방, 날씨 경고
- [ ] 플레이 시간과 이탈 지점을 기록하는 간단한 측정 (개인 정보 없이)

## 4. G1 — 검증 관문

시제품을 실제 사람에게 플레이시키고, 그 결과로 다음을 결정한다. 자세한 근거는 [기획 검증 보고서](04-기획검증.md) 6장에 있다.

### 순서

| 단계 | 방법 | 볼 것 |
|---|---|---|
| 1. 관찰 테스트 | 지인 5~10명에게 설명 없이 플레이시키고 옆에서 지켜봄 | 체온 규칙을 스스로 이해하는가. 폭풍이 올 때 긴장하는가, 귀찮아하는가. 끝나고 "한 번 더"를 하는가 |
| 2. 수정 | 관찰에서 드러난 문제를 고침 (대개 도입부와 안내) | — |
| 3. 공개 테스트 | itch.io와 웹 게임 커뮤니티에 올림. 폭풍 장면의 짧은 영상을 함께 게시 | 아래 지표 |

### 통과 기준 (제안)

| 지표 | 기준 |
|---|---|
| 1분 이상 플레이한 비율 | 80% 이상 |
| 도입부(2분)를 끝까지 본 비율 | 60% 이상 |
| 평균 플레이 시간 | 10분 이상 |
| 자발적 의견 | "날씨" 또는 "폭풍"을 긍정적으로 언급 |

수치 기준은 웹 게임 포털의 평가 기준을 참고한 것이며 출처의 신뢰도가 낮다. 절대적인 합격선이 아니라 판단의 참고값으로 쓴다.

### 결과에 따른 결정

| 결과 | 다음 행동 |
|---|---|
| 통과 | 2단계로 진행 |
| 초반 이탈이 많음 | 도입부와 첫 로딩을 고쳐 다시 테스트 |
| 끝까지 하지만 "한 번 더"가 없음 | 수색의 보상과 귀환 정산을 고쳐 다시 테스트 |
| 날씨가 귀찮다는 반응 | 예고 시간, 빈도, 불이익 강도를 조정. 그래도 같으면 기획의 중심을 다시 검토 |
| 반응이 전반적으로 약함 | 2단계로 가지 않는다. 무엇이 통하지 않았는지 정리하고 기획을 고친다 |

이 관문에서 멈추는 것도 성공적인 결과다. 몇 주의 시제품으로 몇 달의 개발을 아끼는 것이 목적이다.

### G1 통과 후에 할 일

- [ ] 배포와 홍보 계획 수립 (어디에 올리고 어떻게 알릴지). 공개 테스트에서 반응이 온 경로를 근거로 삼는다.
- [ ] (권장, 선택) 멀티플레이 구조 확인 실험: 브라우저 두 개에서 캐릭터 두 명이 같은 구역을 돌아다니고 상자 열림이 공유되는 것까지. 며칠 분량이며 결과물은 버려도 된다. 기술 설계서 18.4 참조.

## 5. 2단계: 수직 슬라이스

G1을 통과한 뒤 진행한다. 시제품의 단순판 시스템을 정식 시스템으로 바꿔 나간다.

### M3 — 전투
- [ ] 체력, 스태미나 컴포넌트와 시스템
- [ ] 근접 공격 (3단 콤보), 공격 판정
- [ ] 구르기와 무적 시간
- [ ] 피해 계산 모듈 + 단위 테스트
- [ ] 적 AI 상태 머신 (대기, 순찰, 추적, 공격, 복귀, 도주)
- [ ] 적 2종: 약탈자(근접), 들개 무리
- [ ] 타격 피드백 (경직, 화면 흔들림, 피해 숫자)
- [ ] 사망 처리 (임시: 대피소에서 부활)
- [ ] 캐릭터 애니메이션 확장 (공격, 구르기, 피격)

### M4 — 아이템/파밍
- [ ] 아이템 데이터 스키마와 로더 (zod 검증)
- [ ] 인벤토리 로직 (추가, 제거, 겹치기, 이동) + 단위 테스트 — 시제품의 단순판 교체
- [ ] 컨테이너와 루트 테이블 + 단위 테스트
- [ ] 적 드롭
- [ ] 무기·복장 장착과 능력치 반영 (방어력, 보온, 통풍)
- [ ] 구역 상태 유지와 내용물 재생성 + 단위 테스트
- [ ] UI: 인벤토리, 장비, 컨테이너 화면

### M5 — 생존/환경 확장
- [ ] 허기 추가, 소모품 사용, 빠른 사용 슬롯
- [ ] 체온 시스템 정식판 (지역 기온, 시간대, 복장 보정, 단계별 불이익) + 단위 테스트
- [ ] 낮/밤 주기 (조명, 하늘 색, 기온 차)
- [ ] 날씨 일정 (시드 기반) + 단위 테스트
- [ ] 폭염 추가
- [ ] 적의 날씨 반응 (폭풍 시 실내로 이동)
- [ ] HUD 확장

### M6 — 제작
- [ ] 레시피 데이터와 제작 로직 + 단위 테스트
- [ ] 맨손 제작, 작업대와 제작 UI
- [ ] 자원 채집 (나무, 고철 더미, 물)
- [ ] 모닥불 (열원, 조리, 물 끓이기)
- [ ] 임시 은신처
- [ ] 무기·복장 내구도와 수리
- [ ] 활과 화살, 조준 (게임패드용 약한 조준 보조 포함)

### M7 — 구역 확장/저장/대피소
- [ ] 구역 3개 추가: 묻힌 마을, 주유소 길목, 양수장 (임시 도형으로 배치 먼저)
- [ ] 건물 프리팹 체계, 소품 자동 흩뿌리기
- [ ] 이동 거점과 빠른 이동 (재난 날씨·전투 중 사용 불가)
- [ ] 인접 구역 미리 받기, 구역 전환 시간 측정
- [ ] 세이브 스키마, 버전 관리, 마이그레이션 구조
- [ ] 저장/불러오기 (플레이어, 월드, 진행, 구역 상태), 자동 저장, 내보내기/가져오기
- [ ] 경험치, 레벨업, 퍽 (갈래별 2~3개)
- [ ] 대피소 시설 복구 로직과 UI + 단위 테스트
- [ ] 사망 시 가방 드롭과 회수

### M8 — 수직 슬라이스 마감
- [ ] 약탈자 두목, 약탈자 사수, 모래잠복체

- [ ] 사운드 (효과음, 환경음, 날씨 소리)

## 6. 의존 관계

- M0 → M1 → M2 → G1은 순서대로 진행한다.
- M3(전투)과 M4(아이템)는 서로 독립적이어서 순서를 바꿀 수 있다.
- M5의 복장 보정은 M4의 장비 장착에 의존한다.
- M6의 모닥불과 임시 은신처는 M5의 열원·대피 판정에 의존한다.
- M7의 구역 3개는 M3~M6의 적과 아이템이 있어야 채울 수 있다.
