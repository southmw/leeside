## 1. 시제품이 답해야 하는 질문

> 폭풍을 피해 가며 폐허를 수색하고 돌아오는 것이 재미있는가? 한 번 더 나가고 싶은가?

시제품에는 이 질문에 필요한 것만 넣는다. 전투, 제작, 허기, 복장, 저장, 성장은 없다.

| 본편과 다른 점 | 시제품 | 이유 |
|---|---|---|
| 하루 길이 | 8분 (본편 24분) | 10분 안에 낮과 밤, 폭풍을 모두 겪게 하려고 |
| 이동 | 한 가지 속도, 스태미나 없음 | 스태미나는 전투와 함께 넣는다 |
| 체온 | 밤의 추위만 | 더위와 복장은 본편에서 |
| 구역 | 마른 강바닥과 대피소 둘 | — |
| 내용물 재생성 | 없음. 폭풍 뒤에 드러나는 물건만 추가됨 | 10분 분량에는 필요 없다 |

## 2. 목표와 보상

### 2.1 목표: 대피소 문 수리

대피소의 출입문은 밀폐가 망가져 있다. 재료를 모아 고치는 것이 시제품의 목표다.

| 필요한 재료 | 수량 |
|---|---|
| 고철 | 15 |
| 천 | 8 |
| 테이프 | 3 |

- 대피소에 돌아오면 가방 속의 해당 재료가 **자동으로 수리에 들어간다.** 제작 화면이 없는 시제품에서 "주운 것이 쓸모 있다"는 것을 보여 주는 방법이다.
- 세 번 정도 다녀오면 채울 수 있는 분량으로 잡았다. 목표 플레이 시간은 10~15분이다.
- 수리 진행도는 귀환 정산 화면과 대피소 문 옆에 표시한다.

**세부 (2.18에서 정함. 초기값)**

| 항목 | 규칙 |
|---|---|
| 들어가는 때 | 귀환 정산이 뜨는 순간(2.3). 가방 속의 고철, 천, 테이프가 가방에서 빠져 수리에 들어간다 |
| 들어가는 양 | 재료마다 **아직 모자란 만큼만.** 그날 주운 것이든 전부터 들고 있던 것이든 가리지 않는다 |
| 남는 재료 | 필요한 수를 채우고 남은 것은 가방에 그대로 남는다. 버려지지 않는다 |
| 진행도 | 재료별 `모은 수 / 필요한 수`. 한번 들어간 것은 줄지 않는다(쓰러져도 잃지 않는다, 2.4) |
| 완료 | 세 재료가 모두 필요한 수에 이르면 완료다. 정산 화면과 문의 안내가 완료로 바뀐다. 끝 화면은 2.24에서 만든다 |
| 대피소의 문 | 북쪽 벽 가운데의 문(임시 도형, 폭 2.4m). 가까이 가서 바라보면 조준점 아래에 진행도가 나온다: `문 수리: 고철 12/15, 천 5/8, 테이프 1/3`. 완료 뒤에는 `수리를 마친 문`. 누르는 키는 없다(재료는 귀환할 때 저절로 들어간다) |
| 다시 시작할 때 | 그만하기(타이틀로)는 진행도를 0으로 되돌린다. 계속하기는 그대로 둔다 |

- 계산은 순수 함수다(`gameplay/repair.ts`): 납품, 진행도의 줄, 완료 판정. 필요한 수는 `tuning.ts`의 `REPAIR_NEEDS`다.
- 진행도는 플레이어가 아니라 대피소의 것이다(멀티플레이에서는 함께 채운다). 지금은 게임이 들고 있다.
- 정산 화면의 "가져온 물건"은 납품하기 전의 가방으로 센다. 그래서 가져온 물건에 적힌 재료가 바로 옆의 수리 진행도에 `(+N)`으로 나타난다. 전부터 들고 있던 재료가 있었다면 `(+N)`이 더 클 수 있다.
- 개발 패널에 수리 항목을 둔다: 지금 진행도, 0으로 되돌리기, 재료마다 하나씩만 남기기(완료 직전을 바로 본다).

### 2.2 한 번의 원정

```
대피소에서 아침 6시에 출발
   → 수색 (해가 지기까지 4분)
   → 그 사이 폭풍이 한 번 온다 (예고 30초 뒤 도달)
   → 폭풍을 건물에서 피하거나, 그 전에 대피소로 돌아온다
   → 귀환 정산: 가져온 물건, 수리 진행도, 생존 일수
   → 다음 날 아침으로
```

플레이어가 매번 고민하는 것은 세 가지다.

1. **폭풍 예고가 떴다. 지금 돌아갈까, 가까운 건물에서 버틸까, 상자 하나만 더 열까?**
2. **가방이 8칸뿐이다. 무엇을 버릴까?**
3. **해가 진다. 밤이 되면 춥다. 지금 돌아갈까?**

### 2.3 귀환 정산

대피소에 들어오면 보여 준다.

- 이번에 가져온 물건 목록
- 수리 진행도 (재료별 `모은 수 / 필요한 수`)
- 생존 일수
- 체력 50 회복
- "다음 날" 버튼

수리 재료가 아닌 물건(물병, 붕대)은 가방에 남는다.

**세부 (2.17에서 정함. 초기값)**

| 항목 | 규칙 |
|---|---|
| 나오는 때 | 강바닥에서 덮개로 대피소에 내려왔을 때마다. 전환의 화면이 다시 밝아지면 뜬다. 대피소에서 게임을 시작했을 때(`?zone=shelter`)와 쓰러진 뒤 다시 시작했을 때는 나오지 않는다 |
| 가져온 물건 | **그날 아침(또는 게임을 시작했을 때) 가방에 있던 것보다 늘어난 만큼**을 물건별로 센다. 줄어든 것(마신 물병)은 적지 않는다. 밖에 버려 두고 온 것은 세지 않는다. 늘어난 것이 없으면 "이번에는 가져온 것이 없습니다" |
| 생존 일수 | 지금이 며칠째인지(끝나는 날을 포함) |
| 체력 | 50 회복. 100을 넘지 않는다. 화면에는 실제로 회복된 만큼을 적는다(체력 80이면 +20). 들어온 순간에 회복된다 |
| 갈증 | **회복되지 않는다.** 물은 물병으로만 채운다(물병을 남겨 올 이유가 된다). 밤을 건너뛰는 동안 줄지도 않는다 |
| 체온 | 대피소 안이므로 쾌적으로 돌아와 있다 |
| 화면이 떠 있는 동안 | 게임 시간이 멈춘다(시계, 갈증). 캐릭터는 서 있고 가방 창은 열리지 않는다 |
| 다음 날 | 버튼, Enter, Esc 모두 같다: 다음 날 06:00이 되고 대피소 안에 그대로 선다. 날씨는 그날의 것이 새로 정해진다 |
| 들어오면 하루가 끝난다 | 대피소에 내려오는 것이 곧 그날을 끝내는 것이다. 폭풍만 피하고 같은 날 다시 나갈 수는 없다(그러려면 강바닥의 건물에서 피한다). 플레이 테스트에서 불편하다는 의견이 많으면 "그냥 쉬기"를 넣는 것을 검토한다 |

- 계산은 순수 함수다(`gameplay/expedition.ts`): 가방의 물건별 개수, 늘어난 만큼, 대피소에서의 회복.
- 수리 진행도의 칸과 막대는 2.18에서 더했다(2.1). 2.17의 화면은 가져온 물건, 회복, 생존 일수, "다음 날" 버튼이었다.
- 개발 패널의 구역 항목에 "귀환(정산 화면)"을 둔다. 폐가 A까지 걸어가지 않고 정산을 본다.

### 2.4 사망

- 체력이 0이 되면 캐릭터가 그 자리에 쓰러지고, 화면이 어두워지며 알림 창이 뜬다. 창에서 **계속하기**와 **그만하기** 중 하나를 고른다(3.4).
- 계속하면 **가방 속의 물건을 그 자리에 떨어뜨리고** 다음 날 아침 대피소에서 다시 시작한다.
- 그만하면 타이틀 화면으로 돌아간다. 거기서 다시 시작하면 처음부터다(1일째, 저장이 없으므로 진행한 것은 남지 않는다).
- 떨어뜨린 가방은 지도상의 그 자리에 남아 있고, 가서 주우면 되찾는다.
- 다시 죽으면 이전에 떨어뜨린 가방은 사라진다.
- 이미 수리에 넣은 재료는 잃지 않는다.

**세부 (2.20에서 정함. 초기값)**

| 항목 | 규칙 |
|---|---|
| 떨어뜨리는 때 | 계속하기를 고른 순간. 가방 속의 모든 물건이 쓰러진 자리의 바닥에 **떨어뜨린 가방** 하나로 놓이고 가방은 빈다. 가방이 비어 있었으면 아무것도 놓이지 않는다 |
| 빠른 사용 칸 | 가방이 비므로 지정도 모두 풀린다(4.5) |
| 다시 시작하는 곳 | **대피소 안**(대피소 구역의 시작 지점), 다음 날 06:00. 체력 100, 갈증 100, 체온 쾌적. 귀환 정산은 나오지 않는다. 대피소 안에서 쓰러졌어도 같다(가방은 대피소 안에 놓인다) |
| 떨어뜨린 가방 | 버린 물건의 더미(4.7)와 같은 틀이지만 모양이 다르다(더 크고 주황색). 버린 물건이 여기에 합쳐지지 않는다. 구역 상태에 남는다(5.5) |
| 되찾기 | 떨어뜨린 가방이 상호작용 대상일 때 E를 한 번 누른다(`[E] 가방 되찾기`). 들어가는 만큼 가방에 넣고, 다 넣으면 떨어뜨린 가방이 없어진다 |
| 나침반 | 떨어뜨린 가방이 지금 있는 구역에 있으면 나침반 바로 아래의 줄에 그 방향과 거리(m)를 표시한다(`marker-bag` 아이콘, 주황색, 깜빡임. 나침반 띠 안에서는 다른 표시와 겹쳐 읽을 수 없었다). 바라보는 쪽에서 벗어나 있으면 가까운 쪽 끝에 화살표와 함께 남는다. 대피소 안에서는(가방이 밖에 있으므로) 나오지 않는다 |
| 빛 기둥 | 떨어뜨린 가방 위에 주황색 빛 기둥(높이 45m)이 선다. 바위와 둑 너머로 보이고, 폭풍의 먼지에도 가려지지 않는다. 나침반만으로는 찾기 어렵다는 직접 확인의 의견으로 더했다(2026-11-23) |
| 다시 쓰러지면 | 계속하기를 고르는 순간 전에 떨어뜨린 가방은 어느 구역에 있든 사라지고, 새로 떨어뜨린 것만 남는다 |
| 알림 창 | 가방에 든 것이 있었으면 "가방은 쓰러진 자리에 남아 있습니다. 그곳으로 돌아가 주우면 되찾을 수 있습니다."를, 전에 떨어뜨린 가방이 아직 있으면 "전에 떨어뜨린 가방은 사라집니다."를 더한다 |
| 수리 | 이미 넣은 재료는 그대로다(2.1) |

- 가방을 비워 묶음으로 만드는 것은 순수 함수다(`gameplay/droppedBag.ts`). 떨어뜨린 가방은 `pile` 컴포넌트에 표시(`dropped`)가 붙은 더미다.

### 2.5 끝

문 수리를 마치면 끝 화면을 보여 준다.

- "시제품은 여기까지입니다"라는 안내
- 플레이 요약: 걸린 시간, 생존 일수, 사망 횟수
- **의견 남기기** 버튼 (외부 설문 주소로 이동. 주소는 배포 단계에서 정함)
- **계속하기** 버튼 (목표 없이 계속 플레이)

수리를 마치지 않고 떠난 사람의 기록도 남는다(플레이 기록, 개발 계획 2.25).

**세부 (2.24에서 정함. 초기값)**

- 수리를 마친 귀환의 정산에서 "다음 날"을 누르면, 다음 날 아침에 끝 화면이 뜬다. 한 게임에 한 번이다.
- 걸린 시간은 플레이 중의 실제 시간이다. 타이틀 화면과 일시정지는 세지 않는다.
- 떠 있는 동안 게임 시간이 멈춘다. "계속 플레이하기"(또는 Esc)로 닫으면 목표 없이 이어진다.
- 설문 주소는 배포 단계(2.27)에서 정한다. 그때까지 의견 남기기 버튼은 넣지 않는다.

### 3.3 폭풍

| 항목 | 도입부 | 이후 |
|---|---|---|
| 예고 시작 | 시작 즉시 | 출발 후 90~180초 사이 (날마다 다름) |
| 예고 길이 | 75초 | 30초 (너무 빠듯하면 늘림) |
| 폭풍 길이 | 40초 | 45~75초 |
| 잦아드는 시간 | 15초 | 15초 |
| 실외 노출 피해 | 초당 4 (체력 30 아래로는 내려가지 않음) | 초당 4 |
| 폭풍 중 시야 | 25m | 25m |
| 오는 방향 | 남쪽 | 남쪽 |

**날씨 상태.** 네 단계를 차례로 지난다(`src/gameplay/weather.ts`).

| 단계 | 길이 | 세기 (0~1) | 접근 (0~1) |
|---|---|---|---|
| 평상시 | 폭풍이 없는 동안 | 0 | 0 |
| 예고 | 30초 (도입부 75초) | 0 | 0에서 1로 오름. 폭풍이 얼마나 가까이 왔는지 |
| 폭풍 | 45~75초 (도입부 40초) | 처음 4초 동안 0에서 1로 오르고 유지 | 1 |
| 잦아듦 | 15초 | 1에서 0으로 내림 | 1에서 0으로 내림 |

- **세기**는 폭풍이 지금 얼마나 센지다. 피해, 시야, 소리가 이 값을 따른다. 예고 중에는 0이다(아직 닿지 않았다).
- **접근**은 예고 중에 폭풍이 다가오는 정도다. 지평선의 폭풍 벽과 커지는 바람 소리가 이 값을 따른다.
- 폭풍은 **날마다 한 번** 온다. 예고가 시작되는 때(출발 후 90~180초)와 폭풍의 길이(45~75초)는 시드와 날짜로 정해져, 같은 시드면 같은 일정이다.
- 일정은 게임 시계를 따른다. 시간 배속을 올리면 폭풍도 빨리 오고, 타이틀 화면에서는 시계가 멈춰 있어 날씨도 멈춰 있다.
- 개발용으로 폭풍을 바로 부르거나(예고부터, 또는 폭풍부터) 그날의 폭풍을 없앨 수 있다.

**폭풍 속의 모습.** 세기에 따라 바뀐다(`src/render/stormLook.ts`). 모두 초기값이다.

| 항목 | 평상시 (세기 0) | 폭풍 (세기 1) |
|---|---|---|
| 시야 | 1,400m. 구역 끝이 지평선 색으로 흐려지는 정도 | 25m. 그 너머는 아무것도 보이지 않음 |
| 공기와 하늘의 색 | 시각에 따른 하늘 색 | 모래색. 세기 0.5에서 하늘이 이미 다 가려짐 |
| 햇빛과 달빛 | 시각에 따른 세기 | 65% 줄어듦 |
| 주변광 | 시각에 따른 세기와 색 | 35% 늘고 모래색을 띰 (먼지가 빛을 흩뜨림). 해가 진 뒤에는 1.5까지 올림 |

- 시야는 세기가 오르는 만큼 같은 비율로 줄어든다(세기 0.5에서 약 190m).
- **시야는 카메라가 아니라 캐릭터에서부터, 모든 방향으로 센다.** 캐릭터를 중심으로 한 반지름 25m의 공 안쪽만 보인다. 카메라는 캐릭터의 뒤나 위로 20m까지 물러날 수 있어서, 카메라에서부터 세면 캐릭터 자신이 먼지에 묻히거나(뒤에서 볼 때) 위에서 내려다볼 때 폭풍이 사라진 것처럼 보인다. 먼지는 시야의 10% 거리(2.5m)에서부터 끼기 시작한다.
- **밤의 폭풍에서는 주변광을 올린다.** 밤은 원래 빛이 적어서, 폭풍이 그 빛마저 줄이면 자기 캐릭터조차 보이지 않았다. 해가 진 뒤의 폭풍에서는 주변광을 1.5로 올려 캐릭터와 가까운 물체가 보이게 한다. 낮에는 적용하지 않는다.
- 먼지의 색은 그때의 밝기를 따른다. 낮에는 모래색, 해 질 무렵에는 붉은 기가 돌고, 밤에는 거의 검다.

**다가오는 폭풍의 벽.** 예고 동안 남쪽에서 다가온다(`src/render/stormWall.ts`). 모두 초기값이다.

| 항목 | 값 |
|---|---|
| 처음 나타나는 거리 | 캐릭터의 남쪽 2,500m. 지평선 위의 낮은 띠로 보임(높이 5° 미만) |
| 높이 | 200m |
| 다가오는 방식 | 일정한 속도가 아니라 남은 거리가 줄어드는 비율로 다가옴. 예고의 절반이 지났을 때 약 500m, 끝날 때 25m |
| 도착 | 예고가 끝나면 폭풍이 시작되며 나머지 25m를 지나 캐릭터를 덮음 |
| 도착한 뒤 | 초속 60m로 북쪽으로 지나가며, 폭풍이 최대 세기가 되는 4초 동안 옅어져 사라짐 |
| 모습 | 공기보다 어두운 먼지 색. 아래는 짙고 위는 밝으며, 먼지 구름이 위로 말려 올라가고 윗선이 꿈틀거림 |

- 벽이 화면에서 차지하는 크기로 남은 시간을 읽는다. 일정한 속도로 오면 예고 대부분 동안 지평선에 붙어 있다가 마지막 순간에 갑자기 하늘을 덮어서, 예고 내내 눈에 띄게 커지도록 다가오는 방식을 바꿨다.
- **다가올수록 주변도 바뀐다.** 예고의 후반으로 갈수록 햇빛이 줄고 하늘이 누렇게 되며 먼 곳이 흐려진다(예고가 끝날 때 폭풍 세기 0.3에 해당하는 모습: 시야 약 420m). 모래 알갱이도 날리기 시작한다.
- 벽 너머에 있는 지형과 건물은 벽의 색에 묻힌다.
- 밤에는 벽이 어두운 하늘에 묻히지 않도록 갈색 기를 남긴다. 모래 알갱이도 밤에 보이도록 밝은 색을 유지한다.
- 폭풍 속에서는 모래 알갱이가 남쪽에서 북쪽으로 화면을 지나간다(초속 26m, 세기에 따라 짙어짐).

**바람 소리.** 바람 소리 하나를 계속 되풀이해 틀고, 날씨와 실내 여부에 따라 크기와 음색을 바꾼다(`src/audio/windMix.ts`). 모두 초기값이다.

| 상황 | 바람의 세기 (0~1) | 음량 (1이 녹음 그대로의 크기) |
|---|---|---|
| 평상시 | 0 | 0.55. 가뭄 평원에 늘 부는 바람 |
| 예고 | 접근을 따라 0에서 0.3으로 고르게 오름 | 0.55에서 약 1.0으로 |
| 폭풍 | 폭풍의 세기 그대로 (4초 동안 1까지) | 2.0 |
| 잦아듦 | 세기를 따라 내려감 | 0.55로 돌아감 |

| 항목 | 값 |
|---|---|
| 실내의 음량 | 실외의 35% |
| 실내의 음색 | 500Hz 위의 높은 소리를 걸러 냄. 벽 너머에서 웅웅거리는 소리가 됨 |
| 실내와 실외 사이의 전환 | 약 1초에 걸쳐 바뀜 |
| 재생 속도 | 평상시 1.0배, 폭풍에서 1.15배. 바람이 더 날카롭고 급하게 들림 |
| 전체 음량 | 80% (설정 화면의 기본값. 설정은 2.22에서 만든다) |

- 직접 들어 보고 두 번 올렸다. 평상시는 0.15에서 0.55로(거의 들리지 않았다), 폭풍은 1.0에서 2.0으로(폭풍치고 작았다).
- 폭풍의 음량은 녹음보다 크다. 그대로 내보내면 큰 돌풍에서 소리가 깨지므로, 출력 직전에 리미터를 두어 최대 크기 바로 아래에서 눌러 준다.
- 폭풍 중의 실내(0.7)는 평상시의 실외(0.55)보다 조금 크지만 먹먹하다.
- 예고 중의 소리는 화면보다 **먼저** 바뀐다. 화면은 예고의 후반에 주로 바뀌지만(접근의 제곱), 소리는 예고가 시작되자마자 고르게 커진다. 벽을 보고 있지 않아도 폭풍이 오는 것을 알게 하려는 것이다.
- 실내는 대피 영역 안이다(3.4). 폭풍의 피해를 막는 판정과 같은 영역을 쓴다.
- 소리는 START를 누른 뒤에 켜진다. 브라우저가 그 전의 소리 재생을 막기 때문이다. 타이틀 없이 시작하면(`?skipTitle`) 처음 키나 마우스를 누를 때 켜진다.
- 창이 가려지면(다른 탭으로 가면) 소리를 멈춘다.
- 음원을 받지 못해도 게임은 소리 없이 돌아간다.
- 음원은 CC0인 바람 녹음 하나(44초, 돌풍이 섞여 있음)다. 출처는 `Src/public/sounds/CREDITS.md`에 있다.

**발소리.** 캐릭터가 땅 위를 움직이면 발소리가 난다(`src/audio/footsteps.ts`). 모두 초기값이다.

| 항목 | 값 |
|---|---|
| 간격 | 달리는 동작의 한 걸음마다 한 번. 지금 캐릭터는 약 2.6m마다이고, 초속 12m에서는 1초에 4~5번 |
| 첫 걸음 | 멈춰 있다가 움직이면 반 걸음(약 1.3m) 뒤에 첫 소리 |
| 착지 | 0.2초 넘게 공중에 있다가 땅에 닿으면 한 번, 가장 큰 소리로. 울퉁불퉁한 땅에서 잠깐 뜨는 것은 세지 않음 |
| 공중 | 소리 없음 |
| 음원 | 소리 8개 중에서 고르되 같은 것을 연달아 틀지 않음 |
| 변화 | 걸음마다 크기(75~100%)와 높낮이(±8%)를 조금씩 다르게 |
| 음량 | 0.25 (바람과 같은 전체 음량 80%를 거침). 처음의 0.5는 너무 컸다 |

- 실내에서도 발소리는 그대로다. 땅의 종류(흙, 건물 바닥)에 따라 소리를 바꾸지는 않는다.
- 폭풍 속에서는 바람 소리에 묻혀 잘 들리지 않는다.
- 발소리는 녹음이 아니라 변환 스크립트가 잡음으로 만든 소리다(`scripts/build-sounds.mjs`): 둔탁한 쿵 소리에 모래 밟는 소리가 뒤꿈치와 앞꿈치로 두 번 겹친다. 처음에는 Kenney의 발소리 녹음(CC0)을 썼는데, 딱딱한 바닥을 구두로 걷는 소리라 1초에 다섯 번 뛰는 흙길과 어울리지 않았다.

체력 100으로 폭풍 속에서 버틸 수 있는 시간은 25초, 이동 거리로는 약 160m다. 건물이 그 안에 없으면 죽는다. (폭풍이 닿은 직후 4초 동안은 세기가 오르는 중이라 피해가 적어서, 닿는 순간부터 세면 약 27초다. 3.4)

예고 30초 동안 달릴 수 있는 거리는 약 195m다. 도입부만 75초로 길게 둔 것은 조작을 익히는 시간이 필요하기 때문이다.

### 3.4 생존 수치

| 항목 | 값 |
|---|---|
| 체력 | 최대 100. 귀환 시 50 회복 |
| 갈증 | 100에서 시작, 10분에 0. 0이면 체력이 초당 1 감소 |
| 체온 (밤, 실외) | 쾌적 → 추움 60초 → 저체온 60초 더 |
| 저체온 피해 | 체력 초당 2 감소 |
| 체온 회복 | 실내에서 20초에 쾌적으로 |
| 가방 | 8칸 |
| 상자 수색 시간 | 1.5초 (누르고 있기) |

**체력과 폭풍의 피해.** 계산은 순수 함수다(`src/gameplay/health.ts`).

| 항목 | 값 |
|---|---|
| 체력 | 100에서 시작. 최대 100, 최소 0 |
| 폭풍의 피해 | 대피 영역 밖에서 초당 4 × 세기(3.3). 세기가 1이면 25초에 100이 0이 된다 |
| 대피 영역 안 | 피해 없음 |
| 체력이 0이 되면 | 쓰러지고, 1.5초 뒤 알림 창이 뜬다. 계속하기 또는 그만하기 |
| 계속하기 | 가방을 쓰러진 자리에 떨어뜨리고, 대피소 안에서, 다음 날 아침에, 체력 100으로 다시 시작(2.4. 2.20에서 만듦. 그 전에는 임시로 폐가 A 안에서 가방을 든 채 다시 시작했다) |
| 그만하기 | 타이틀 화면으로. 게임은 처음 상태로 돌아간다 |

- 피해는 세기를 따른다. 예고 중에는 없고, 폭풍이 닿은 뒤 4초 동안 커지고, 잦아드는 15초 동안 줄어든다.
- 피해는 게임 시간으로 센다. 시간 배속을 올리면 폭풍이 짧아지는 만큼 피해도 빨라져서 폭풍 한 번의 피해량은 같다. 시계를 멈추면 피해도 멈춘다.
- 체력은 플레이어마다 따로 둔다(`health` 컴포넌트).
- **쓰러짐.** 체력이 0이 되면 캐릭터가 쓰러지는 동작(캐릭터 팩의 `Death`, 0.77초)을 한 번 하고 누운 채로 있는다. 모델을 받지 못해 캡슐로 그릴 때는 동작이 없다. 캐릭터는 뒤로(카메라 쪽으로) 쓰러지므로, 카메라가 1초에 걸쳐 7m 이상으로 물러나고 49° 이상 내려다보아 쓰러진 모습이 화면에 들어오게 한다(거리와 각도는 초기값). 쓰러진 동안 이동과 점프는 듣지 않고 시점은 돌릴 수 있다. 세계는 멈추지 않는다: 시계가 가고 폭풍도 계속 분다(창을 열어도 게임은 흐른다는 원칙).
- **알림 창.** 쓰러진 뒤 1.5초 동안 화면이 어두워지고 창이 뜬다. 원인 한 줄(지금은 폭풍뿐)과 버튼 두 개가 있다. 처음 골라져 있는 것은 계속하기다. Esc로 창을 닫으면 계속하기로 친다. 1.5초는 초기값이다.
- **그만하기.** 타이틀 화면으로 돌아가고 게임은 처음 상태가 된다: 시작 위치, 1일째 06:00, 체력 100, 사망 횟수 0, 날씨는 새 시드(`?seed`를 준 경우는 그대로). 페이지를 다시 불러오지 않으므로 바로 START를 누를 수 있다.
- 계속하기의 처리는 임시다. 가방을 떨어뜨리는 것과 가방 안내 문구는 2.20에서, 실제 대피소 구역은 2.16에서 만든다. 다시 시작할 때의 체력 100은 초기값이다.
- 도입부에서 체력이 30 아래로 내려가지 않는 것(3.3)은 도입부(2.23)에서 넣는다.
- 화면 아래 왼쪽에 체력 막대(이름, 수치, 막대)가 나온다. 체온과 갈증의 막대, 아이콘, 위험할 때의 깜빡임, 피해 원인 표시는 2.9~2.11에서 붙인다.

**체온.** 시제품에서는 밤의 추위만 다룬다. 계산은 순수 함수다(`src/gameplay/temperature.ts`).

| 항목 | 값 |
|---|---|
| 값의 범위 | -100(가장 추움) ~ 0(쾌적) ~ +100(더위). 시제품에서는 0 아래만 쓴다. 0에서 시작 |
| 단계 | 쾌적(-50보다 높음), 추움(-50 이하), 저체온(-100) |
| 내려가는 때 | 밤(19:00~05:00)에 대피 영역 밖. 초당 100/120(약 0.83): 60초에 추움, 120초에 저체온 |
| 올라가는 때 | 그 밖의 모든 때(대피 영역 안, 낮과 해 질 무렵의 실외). 초당 5: 저체온에서 20초에 쾌적으로. 0에서 멈춘다 |
| 저체온의 피해 | 체력 초당 2 감소. 100에서 50초 |

- **화면에서는 "온도"라고 부른다**(영어 "Temperature"). 값이 0, -50, -95처럼 움직이는데 "체온"이라고 하면 사람의 체온으로 읽혀 말이 되지 않기 때문이다(사용자 결정, 2026-11-18). 문서와 코드에서는 수치의 이름으로 체온(`temperature`)을 그대로 쓴다.
- 추움 단계는 경고다. 피해가 없고 화면에 단계 이름이 나온다.
- 낮의 실외에서도 실내와 같은 속도로 돌아온다. 설계에는 실내의 회복만 있었는데, 그대로 두면 밤을 밖에서 넘긴 뒤 낮에도 계속 얼어 있게 되어 넣었다(초기값).
- 폭풍은 체온에 영향을 주지 않는다. 폭풍 속에서도 낮이면 체온은 그대로다.
- 체력의 피해와 같이 게임 시간으로 센다. 시간 배속을 올리면 밤이 짧아지는 만큼 빨리 식는다.
- 체온은 플레이어마다 따로 둔다(`temperature` 컴포넌트). 다시 시작하면(계속하기, 그만하기) 0으로 돌아간다.
- **사망 원인.** 체력에 마지막으로 피해를 준 것을 기억해 두고(`health.lastHurtBy`: 폭풍, 추위), 사망 알림 창의 문구를 거기에 맞춘다.
- 화면 아래 왼쪽, 체력 막대 아래에 체온 막대가 나온다. 가운데가 쾌적이고 추울수록 푸른 막대가 왼쪽으로 자란다. 막대 위에 이름과 단계(쾌적, 추움, 저체온)를 글자로 적는다. 아이콘, 깜빡임, 화면 가장자리가 푸르게 변하는 효과는 2.11에서 붙인다.

**갈증.** 계산은 순수 함수다(`src/gameplay/thirst.ts`).

| 항목 | 값 |
|---|---|
| 값의 범위 | 100(목마르지 않음) ~ 0(바닥). 100에서 시작 |
| 줄어드는 속도 | 초당 100/600: 10분에 0. 어디에 있든, 낮이든 밤이든 같다 |
| 0일 때의 피해 | 체력 초당 1 감소. 100에서 100초 |
| 회복 | 물병 하나에 40. 100을 넘지 않는다. 물병을 마시는 조작은 2.15에서 붙인다 |

- 체력의 피해, 체온과 같이 게임 시간으로 센다. 하루가 8분이므로 갈증은 하루하고 2분을 버틴다.
- 갈증은 플레이어마다 따로 둔다(`thirst` 컴포넌트).
- 다시 시작하면(계속하기, 그만하기) 100으로 돌아간다. 갈증으로 죽은 뒤 0인 채로 일어나면 곧바로 다시 죽기 때문이다(초기값). 귀환 정산에서는 갈증을 회복하지 않는다(2.3, 2.17에서 정함).
- 사망 원인에 갈증이 더해진다(`health.lastHurtBy`: 폭풍, 추위, 갈증).
- 화면 아래 왼쪽, 체온 막대 아래에 갈증 막대(이름, 수치, 물색 막대)가 나온다. 20 이하일 때의 깜빡임과 아이콘은 2.11에서 붙인다.

**대피 영역.** 폭풍과 밤의 추위를 피할 수 있는 곳이다(`src/gameplay/shelter.ts`). 안에 있으면 폭풍의 피해를 받지 않고(2.8), 체온이 돌아오고(2.9), 바람 소리가 줄어든다(3.3).

| 항목 | 값 |
|---|---|
| 대피 영역이 되는 곳 | 구역 정의에서 대피할 수 있다고 표시한 건물(`shelter`). 마른 강바닥은 폐가 A, B, C 모두 |
| 범위 (수평) | 건물의 바깥 벽 안쪽 전체. 건물과 함께 회전한다. 경계선 위는 안으로 친다 |
| 범위 (수직) | 건물 바닥 아래 0.5m부터 벽의 높이까지. 지붕 위는 밖이다 |
| 판정하는 기준 | 캐릭터의 중심. 문턱에서는 몸의 절반이 들어오면 안이다 |
| 차단 정도 | 한 가지(완전히 막음). 본편의 "차단 정도"(기술 설계서의 `shelterZone` 컴포넌트)는 쓰지 않는다 |

- 문이 뚫려 있어도 안은 안이다. 문 앞에 서 있어도 피해를 받지 않는다.
- 판정은 60Hz 틱마다 하고 결과를 플레이어마다 따로 둔다(`shelter` 컴포넌트). 소리와 화면 표시, 앞으로의 피해와 체온이 모두 이 값을 읽는다.
- 대피 영역은 엔티티다(`shelterZone` 컴포넌트와 위치). 구역을 올릴 때 건물에서 만들고 내릴 때 지운다.
- 안에 있는 동안 화면 아래 오른쪽에 "대피 중"이 나타난다. 폭풍 중(세기가 0보다 클 때)에는 모래색 바탕으로 강조된다(UI 설계 5장). 아이콘은 HUD 단계(2.11)에서 붙인다.
- 개발 패널(F2)에서 대피 영역을 초록색 상자로 표시할 수 있다. 벽 너머에서도 보인다.

### 3.5 상호작용 (2.12)

가까이 있고 바라보는 대상 하나를 골라, E로 무엇을 할 수 있는지 알려 준다. 대상은 상자, 버린 물건의 더미(4.7), 구역의 출입구(5.5)다. 출입구도 E로 쓰고 같은 규칙으로 고른다(2.16에서 정함). 수치는 초기값이다.

| 항목 | 값 |
|---|---|
| 거리 | 캐릭터의 중심에서 대상의 상호작용 지점까지 수평으로 2m 이하 |
| 높이 | 캐릭터의 발과 대상이 놓인 바닥의 높이 차이가 1.5m 이하. 위층이나 지하의 대상이 바닥 너머로 잡히지 않게 한다. 점프(1.1m) 중에는 그대로 잡힌다 |
| 방향 | 시점이 보는 수평 방향과, 캐릭터에서 대상으로 가는 방향의 차이가 60° 이하 |
| 방향의 기준 | 캐릭터의 몸이 아니라 시점(카메라가 보는 쪽). 몸은 움직이는 쪽으로 돌기 때문에, 서서 시점만 돌려 고를 수 있게 한다. 카메라의 위아래 각도는 따지지 않는다 |
| 아주 가까울 때 | 대상까지 0.3m 이하면 방향을 따지지 않는다. 대상 위에 서 있으면 방향이 정해지지 않기 때문이다 |
| 가로막힘 | 캐릭터와 대상 사이에 벽, 바위, 다른 물체가 있으면 고르지 않는다. 집 안의 수납장이 벽 너머 밖에서 잡히지 않게 한다. 대상 자신(수납장과 야외 상자의 도형, 트렁크의 차량)은 가로막는 것으로 치지 않는다 |
| 여럿일 때 | 방향의 차이가 가장 작은 것. 같으면 가까운 것. 가로막힌 것은 건너뛰고 다음 것을 고른다 |

- 고르는 것은 순수 함수다(`gameplay/interaction.ts`). 캐릭터의 위치, 시점의 방향, 후보 목록을 넣으면 고른 대상(또는 없음)이 나온다. 가로막혔는지는 물리 월드에 물어본다: 캐릭터의 중심에서 대상의 바닥 위 0.5m까지 직선을 그어 처음 닿는 물체를 본다.
- 대상은 엔티티다(`interactable` 컴포넌트: ID와 할 수 있는 일의 종류. 상호작용 지점은 엔티티의 위치다). 구역을 올릴 때 상자마다 만들고 내릴 때 지운다. 기술 설계서 6장의 `interactable`에는 대상마다의 범위가 있지만, 시제품에서는 모든 대상이 같은 거리(2m)를 쓰므로 넣지 않는다.
- 60Hz 틱마다 고르고 결과를 플레이어마다 따로 둔다(`interaction` 컴포넌트에 대상의 ID). 화면의 안내는 이 값을 읽는다.
- 대상이 있으면 화면 가운데의 조준점 아래에 키와 동작이 나온다(UI 설계 5장). 대상에서 멀어지거나 시점을 돌리면 사라진다.
- 2.12에서는 고르고 알려 주는 데까지만 한다. E를 눌러도 아무 일도 일어나지 않는다. 1.5초 누르기와 상자 열기는 2.14에서 붙인다.
- 쓰러져 있는 동안에는 고르지 않는다.

## 4. 물건

### 4.1 목록

| 물건 | 쓰임 | 한 칸에 겹치는 수 |
|---|---|---|
| 고철 | 수리 재료 | 5 |
| 천 | 수리 재료 | 5 |
| 테이프 | 수리 재료 | 5 |
| 물병 | 마시면 갈증 40 회복 | 3 |
| 붕대 | 쓰면 체력 30 회복 | 3 |

시작할 때 가방은 비어 있다. 도입부의 차량에서 물병 1개와 천 2개가 반드시 나온다.

### 4.2 상자에 물건을 넣는 방식

**수리에 필요한 재료는 반드시 나온다. 어느 상자에서 나오는지만 매번 다르다.** 상자의 내용물은 게임을 시작할 때 두 단계로 정한다.

**1단계: 보장 물량 배분**

수리에 필요한 재료 전부(고철 15, 천 8, 테이프 3)를 상자들에 무작위로 나눠 넣는다.

| 재료 | 보장 수량 | 들어갈 수 있는 상자 | 상자 수 |
|---|---|---|---|
| 고철 | 15 | 차량 트렁크, 야외 상자 | 7 |
| 천 | 8 (그중 2개는 도입부 차량에 고정) | 집 안 수납장, 야외 상자 | 10 |
| 테이프 | 3 | 차량 트렁크, 집 안 수납장 | 9 |

상자 수는 내용물이 고정된 도입부 차량 트렁크를 뺀 것이다. 고철은 상자 7개에 최대 3개씩 21개까지 들어갈 수 있어 15개를 넣는 데 여유가 있다.

- 한 상자에 보장 물량은 한 재료당 최대 3개까지만 들어간다. 한 곳에 몰리지 않게 하기 위해서다.
- 재료가 어울리는 상자에만 들어간다(천은 집 안에서, 고철은 차량과 야외에서).
- 도입부의 차량 트렁크는 물병 1개와 천 2개로 고정이다.
- 배분은 시드로 정한다. 게임을 새로 시작할 때마다 시드가 바뀌어 위치가 달라지고, 같은 시드면 같은 배치가 나온다(`?seed`로 지정 가능).

**2단계: 추가 뽑기**

보장 물량과 별개로 상자마다 물건을 더 뽑는다. 물병과 붕대는 여기서만 나온다. 숫자는 나올 확률의 비중이다.

| 상자 종류 | 뽑는 횟수 | 고철 | 천 | 테이프 | 물병 | 붕대 |
|---|---|---|---|---|---|---|
| 차량 트렁크 | 1 | 30 | — | 10 | 40 | 20 |
| 집 안 수납장 | 1 | — | 25 | 10 | 40 | 25 |
| 야외 상자 | 0~1 | 40 | 30 | — | 30 | — |

한 번 뽑을 때 수량은 1~2개다. 그래서 상자가 비어 있는 일은 드물지만, 보장 물량이 배정되지 않은 야외 상자는 빌 수 있다.

**폭풍 뒤에 드러나는 물건**

폭풍이 끝날 때마다 4곳에 재료가 하나씩 생긴다. **수리에 아직 모자란 재료가 우선해서 나온다.** 사망으로 재료를 잃어 상자만으로는 채울 수 없게 된 경우에도 목표를 끝낼 수 있게 하는 안전장치다. 모자란 재료가 없으면 고철 60, 천 25, 테이프 15의 비중으로 나온다.

**세부 (2.19에서 정함. 초기값)**

| 항목 | 규칙 |
|---|---|
| 후보 지점 | 강바닥의 물길을 따라 12곳(구역 정의의 `revealSpots`). 남북으로 50m 간격이고 물길 가운데에서 좌우로 조금씩 벗어나 있다. 바위는 이 지점의 둘레 1.5m를 피한다 |
| 생기는 때 | 폭풍이 잦아들기 시작할 때(날씨가 "폭풍"에서 벗어나는 순간). 플레이어가 대피소 안에 있어도 강바닥에 생긴다. 하루를 넘겨 폭풍이 끝난 경우에도 생긴다 |
| 고르는 지점 | 12곳 중 서로 다른 4곳. 게임의 시드와 몇 번째 폭풍인지로 정해져, 같은 시드면 같은 곳이다 |
| 모자란 재료 | 재료마다 `필요한 수 − 수리에 들어간 수 − 가방에 든 수`가 모자란 수다. 모자란 비율(모자란 수 ÷ 필요한 수)이 가장 큰 재료부터 하나씩 고르고, 고를 때마다 그 재료의 모자란 수를 하나 줄인다. 그래서 처음에는 고철, 천, 테이프가 섞여 나온다 |
| 모자란 것이 없을 때 | 고철 60, 천 25, 테이프 15의 비중으로 뽑는다 |
| 모양 | 버린 물건의 더미(4.7)와 같다: 지점마다 재료 하나가 든 더미가 놓이고 `[E] 줍기`로 줍는다. 줍지 않으면 남고, 다음 폭풍 뒤에 같은 지점이 다시 뽑히면 더미가 하나 더 놓인다 |

- 고르는 것은 순수 함수다(`gameplay/reveal.ts`). 상자 안이나 바닥에 있는 재료는 세지 않는다: 플레이어가 지금 쥐고 있는 것과 이미 수리에 넣은 것만 센다.
- 한 번에 4개이므로, 재료를 모두 잃어도 폭풍 일곱 번이면 수리에 필요한 26개가 다 나온다.

### 4.3 물량 점검

| 구분 | 수량 |
|---|---|
| 수리에 필요한 재료 | 26개 (고철 15, 천 8, 테이프 3) |
| 상자의 보장 물량 | 26개. 필요한 수량과 같다 |
| 상자의 추가 뽑기 | 도입부 차량을 뺀 상자 13개에서 약 17개 (재료, 물병, 붕대가 섞여 있음) |
| 폭풍 뒤 드러나는 물건 | 폭풍마다 4개. 모자란 재료 우선 |

모든 상자를 열면 수리를 반드시 끝낼 수 있다. 추가 뽑기와 폭풍 뒤의 물건 덕분에 실제로는 상자를 전부 열지 않아도 된다. 가방을 잃어버려도 폭풍 뒤의 물건으로 채울 수 있다.

### 4.4 가방 (2.13)

가방은 8칸이고, 한 칸에는 한 가지 물건이 4.1의 겹치는 수까지 들어간다. 정해지지 않았던 세부를 여기서 정한다(초기값).

| 항목 | 규칙 |
|---|---|
| 넣기 | 같은 물건이 든 덜 찬 칸을 앞에서부터 먼저 채우고, 남으면 앞의 빈 칸부터 새로 쓴다 |
| 다 들어가지 않을 때 | 들어가는 만큼만 넣고 나머지는 원래 있던 곳에 남긴다. 하나도 들어가지 않으면 거부한다 |
| 빼기 (물건을 지정) | 그 물건이 든 칸 중 뒤의 칸부터 줄인다. 덜 찬 칸이 흩어지지 않게 하기 위해서다 |
| 버리기 (칸을 지정) | 그 칸에서 한 개를 뺀다. 다 빼면 칸이 빈다. 뒤의 칸을 앞으로 당기지 않는다(칸의 위치가 바뀌면 화면에서 물건이 뛰어다닌다) |
| 가득 참 | 빈 칸이 하나도 없을 때. 덜 찬 칸이 있어 같은 물건은 더 들어가더라도 가득 찬 것으로 표시한다 |
| 다시 시작할 때 | 그만하기(타이틀로)는 가방을 비운다. 계속하기는 지금은 가방을 그대로 둔다(가방을 떨어뜨리는 것은 2.20) |

- 물건의 정의는 한 곳에 둔다(`src/data/items.ts`): ID(`scrap`, `cloth`, `tape`, `water_bottle`, `bandage`), 이름의 문구 항목, 아이콘, 겹치는 수, 분류(수리 재료, 쓰는 물건), 쓸 때의 효과. 화면은 이 정의를 ID로 찾아 쓴다.
- 가방은 플레이어의 `inventory` 컴포넌트이고 칸의 배열이다. 계산은 순수 함수다(`gameplay/inventory.ts`).
- **가방을 바꾸는 일은 명령을 거친다**(기술 설계서 18장). 명령은 누가(엔티티의 ID), 무엇을 하는지를 담은 단순한 값이고, 60Hz 틱 안에서 차례로 처리된다(`gameplay/commands.ts`). 2.13의 명령은 물건 주기(개발용)와 버리기 둘이다. 상자에서 가져가기(2.14), 쓰기(2.15)가 같은 틀에 더해진다. 명령을 가리킬 수 있게 플레이어 엔티티에 ID를 준다.
- 버린 물건은 발밑에 놓여 다시 주울 수 있다(4.7, 2.15에서 만듦. 2.13에서는 버리면 없어졌다).
- **가방 속은 가방 창(Tab)에서 본다.** 화면 아래의 칸은 가방이 아니라 빠른 사용 칸이다(4.5). 플레이 중의 화면에는 가방의 찬 칸 수만 나온다(UI 설계 5장, 7장).
- 가방을 채운 채 시작하는 시작 조건 `?bag=scrap:7,water_bottle:2`와 개발 패널의 가방 항목(물건 주기, 버리기, 비우기)을 둔다. 2.14 전에는 물건을 얻을 방법이 이것뿐이다.

### 4.6 상자 수색 (2.14)

상자의 내용물을 정하는 방식은 4.2에 있다. 여기서는 여는 방법과 가져가는 방법을 정한다. 수치는 초기값이다.

| 항목 | 규칙 |
|---|---|
| 처음 열기 (수색) | 상자가 상호작용 대상일 때(3.5) E를 1.5초 누르고 있는다. 누르는 동안 조준점 둘레의 고리가 찬다 |
| 수색이 취소되는 때 | E를 뗐을 때, 움직였을 때(이동 입력이나 점프), 대상이 바뀌거나 없어졌을 때, 쓰러졌을 때. 처음부터 다시 눌러야 한다 |
| 다 누르면 | 상자가 열린 상태가 되고, 내용물이 있으면 상자 패널이 뜬다(UI 설계 6장). 비어 있으면 패널 없이 안내가 "비어 있음"으로 바뀐다 |
| 이미 연 상자 | 남은 물건이 있으면 E를 한 번 눌러 바로 다시 연다(안내는 "열기"). 비어 있으면 열 수 없고 안내에 "비어 있음"만 나온다 |
| 가져가기 | 고른 물건의 묶음 전체를 가방에 넣는다. 다 들어가지 않으면 들어가는 만큼만 넣고 나머지는 상자에 남는다(4.4) |
| 모두 가져가기 | 위에서부터 차례로 같은 방법으로 넣는다 |
| 패널이 닫히는 때 | 다 가져갔을 때, 상자에서 2m 넘게 멀어졌을 때, Esc나 닫기를 눌렀을 때, 쓰러졌을 때 |
| 열린 모양 | 수납장과 야외 상자는 색이 어두워지고, 트렁크는 차 뒤에 열린 덮개가 생긴다. 남은 물건이 있든 없든 같다 |

**추가 뽑기의 세부** (4.2의 2단계에서 정하지 않은 것)

- 야외 상자의 "0~1회"는 절반의 확률로 한 번이다.
- 한 번 뽑을 때의 수량 1~2개는 같은 확률이다.
- 도입부의 고정 트렁크는 추가로 뽑지 않는다.
- 같은 물건이 보장 물량과 추가 뽑기에서 함께 나오면 한 묶음으로 합친다. 상자 안에서는 겹치는 수의 제한이 없다(가방에 넣을 때 나뉜다).

**구조**

- 내용물은 게임을 시작할 때 시드로 한 번 정한다(`gameplay/loot.ts`, 순수 함수). 시드는 날씨와 같은 값(`?seed`)에서 갈라 쓴다. 그만하기로 타이틀에 돌아가면 새 시드로 다시 채우고 모두 닫는다.
- 상자의 상태(열렸는지, 남은 물건)는 상자 엔티티의 `container` 컴포넌트에 있다. 구역을 다시 올려도(소품 묶음 바꾸기, 2.16의 구역 전환) 상태는 남는다.
- 여는 것과 가져가는 것은 명령이다(`openContainer`, `takeItem`, `takeAll`). 명령은 그 사람이 상자에서 닿는 거리에 있는지, 상자가 열려 있는지를 확인하고, 아니면 거부한다.
- 수색의 진행(누른 시간)은 플레이어마다 따로 가진다. 실제 시간으로 세고 시간 배속의 영향을 받지 않는다.
- 내용물이 고정된 상자는 구역 정의에 적는다(`contents`).

### 4.5 빠른 사용 칸 (2.15)

화면 아래의 4칸이다. 숫자 키 1~4로, 가방을 열지 않고 물건을 쓴다. 본편의 빠른 사용 슬롯(게임 기획서 5.2, 1~4)과 같다. 수치는 초기값이다.

| 항목 | 규칙 |
|---|---|
| 칸 수와 키 | 4칸, 키 1~4 |
| 칸이 가리키는 것 | 물건의 종류. 물건을 담지 않는다. 칸에 지정된 물건도 가방의 자리를 그대로 차지하고, 가방의 8칸 제한은 달라지지 않는다 |
| 개수 | 가방의 모든 칸에 든 그 물건의 합 |
| 지정할 수 있는 것 | **쓸 수 있는 물건과 무기뿐이다.** 쓸 수 있는 물건은 누르면 하나를 쓰고, 무기는 누르면 그 무기로 바꿔 든다. 시제품에는 무기가 없어 물병과 붕대만 해당한다. 수리 재료는 지정할 수 없다 |
| 처음의 지정 | 없다. 네 칸 모두 비어 있고, 플레이어가 직접 지정한다 |
| 지정하기 | 가방 창에서 물건을 고르고 1~4를 누른다. 그 물건이 다른 칸에 있었으면 두 칸의 내용을 맞바꾼다. 한 물건은 한 칸에만 지정된다 |
| 지정 풀기 | 가방 창에서 지정된 물건을 고르고 그 칸의 번호를 다시 누른다 |
| 가방에서 다 없어졌을 때 | 마지막 하나가 가방에서 나가면 지정이 풀려 칸이 빈다. 써서 없어졌든(숫자 키, 가방 창) 버려서 없어졌든 같다. 그래서 칸에 0개가 표시되는 일은 없다. 다시 얻으면 다시 지정한다. 2.15의 직접 확인에서 정했다(처음에는 0개로 남겼다) |
| 쓰기 | 키를 누르면 그 물건을 하나 쓴다. 가방에서는 뒤의 칸부터 줄어든다(4.4의 빼기) |
| 쓸 수 없을 때 | 칸이 비어 있거나, 채울 것이 없을 때(갈증 100에서 물병, 체력 100에서 붕대). 물건이 줄지 않는다 |

- 지정은 플레이어마다 따로 가진다(`quickSlots` 컴포넌트: 칸마다 물건의 ID 또는 비어 있음). 지정을 바꾸는 것과 쓰는 것은 명령을 거친다.
- 지정할 수 있는지는 물건의 정의가 정한다(`data/items.ts`): 쓸 때의 효과가 있는 물건, 그리고 본편에서 더해질 무기 분류. 화면과 명령이 같은 판정을 쓴다.
- 지정하지 않은 물건은 가방 창의 사용 버튼으로 쓴다. 도입부에서 첫 물병을 주웠을 때 지정하는 법을 안내한다(2.23).
- 쓰는 것의 판정은 한 곳에 둔다(`gameplay/itemUse.ts`, 순수 함수). 숫자 키로 쓰든 가방 창에서 쓰든 같은 판정을 거친다. 쓰러진 캐릭터는 쓸 수 없다.
- 숫자 키는 누르는 순간 한 번만 친다(누르고 있어도 하나만 쓴다). 가방 창이 열려 있는 동안 숫자 키는 지정에 쓰이고 물건을 쓰지 않는다.

### 4.7 버린 물건 (2.15)

가방 창에서 버린 물건은 없어지지 않고 발밑에 놓인다. 가방이 차서 잠깐 내려놓은 것을 다시 주울 수 있게 하기 위한 것이다. 수치는 초기값이다.

| 항목 | 규칙 |
|---|---|
| 놓이는 곳 | 버린 사람의 발밑(서 있는 바닥). 공중에서 버리면 바로 아래의 바닥 |
| 더미 | 놓인 물건은 **더미** 하나로 모인다. 버린 곳에서 1m 안에 더미가 있으면 거기에 더해지고, 없으면 새 더미가 생긴다. 더미 안에서는 같은 물건이 한 묶음이고 겹치는 수의 제한이 없다(상자 안과 같다) |
| 줍기 | 더미가 상호작용 대상일 때(3.5) E를 한 번 누른다. 더미의 물건을 위에서부터 가방에 넣는다. 다 들어가지 않으면 들어가는 만큼만 넣고 나머지는 더미에 남는다(4.4) |
| 없어지는 때 | 다 주우면 더미가 없어진다. 그만하기로 타이틀에 돌아가면 모두 없어진다. 계속하기(사망 뒤)에서는 남는다 |
| 모양 | 작은 자루 모양의 임시 도형(0.4 × 0.2 × 0.3m). 든 물건에 따라 달라지지 않는다. 길을 막지 않는다(충돌 없음) |
| 안내 | 조준점 아래에 `[E] 줍기` |

- 더미는 엔티티다(`pile` 컴포넌트: 든 물건의 목록). 상자처럼 `interactable`을 가지므로 대상 선택(3.5)의 규칙을 그대로 따른다. 구역이 아니라 게임이 들고 있어 구역을 다시 올려도 남는다.
- 버리기(`discardItem`)가 더미를 만들거나 더하고, 줍기(`pickUp`)가 더미에서 가방으로 옮긴다. 둘 다 명령이고, 줍기는 닿는 거리 안에서만 된다. 물건의 총수는 버리고 주워도 그대로다.
- 발밑의 더미는 방향을 따지지 않고 대상이 되므로(3.5의 0.3m 규칙), 버린 자리에 그대로 서 있으면 앞의 상자보다 더미가 먼저 잡힌다. 상자 패널이 열려 있는 동안에는 E가 패널의 것이어서 문제가 되지 않는다.
- 개발 패널의 "비우기"는 더미를 남기지 않고 없앤다(개발용 명령 `destroyItem`).
- 폭풍 뒤에 드러나는 물건(4.2, 2.19)과 사망 때 떨어뜨리는 가방(2.20)은 이 더미와 따로 만든다. 같은 틀을 쓸지는 그 단계에서 정한다.

#### 상자의 위치 (2.12)

상자 14개는 구역 정의에 넣는다(`containers`). 위치와 종류만 정하고, 내용물은 2.14에서 시드로 정한다. 위치와 크기는 초기값이다.

| 종류 | 임시 모양 | 상호작용 지점 |
|---|---|---|
| 차량 트렁크 | 따로 그리지 않는다. 차량이 곧 상자다 | 차량의 뒤쪽 끝 가운데 |
| 집 안 수납장 | 상자 도형. 가로 1.0m, 깊이 0.5m, 높이 1.2m. 벽에 붙임 | 수납장의 가운데 |
| 야외 상자 | 상자 도형. 가로 0.9m, 깊이 0.6m, 높이 0.6m | 상자의 가운데 |

수납장과 야외 상자는 충돌이 있어 통과하지 못한다. 모델로 바꾸는 것과 열린 모양은 2.14에서 정한다(후보는 에셋 후보 문서에 있다: Zombie Apocalypse Kit의 Chest).

| ID | 종류 | 장소 | 위치 |
|---|---|---|---|
| `car_line_trunk` | 트렁크 | 1 차량 행렬 | 첫째 차량(`car_line`)의 뒤 |
| `car_line_second_trunk` | 트렁크 | 1 차량 행렬 | 둘째 차량(`car_line_second`)의 뒤 |
| `abandoned_car_trunk` | 트렁크 | 2 버려진 차량 | 차량의 뒤 |
| `overturned_car_trunk` | 트렁크 | 3 뒤집힌 차량 | 차량의 뒤 |
| `house_a_cabinet_back`, `house_b_cabinet_back`, `house_c_cabinet_back` | 수납장 | 폐가 A, B, C | 문 맞은편 벽에 붙여, 벽의 가운데에서 북쪽으로 2m |
| `house_a_cabinet_side`, `house_b_cabinet_side`, `house_c_cabinet_side` | 수납장 | 폐가 A, B, C | 남쪽 벽에 붙여, 벽의 가운데에서 문 반대쪽으로 2m |
| `overturned_car_crate` | 야외 상자 | 3 뒤집힌 차량 | (247, 566). 차량의 옆으로 4m |
| `camp_crate_north` | 야외 상자 | K 야영지 흔적 | (209, 147) |
| `camp_crate_south` | 야외 상자 | K 야영지 흔적 | (203, 155) |
| `well_crate` | 야외 상자 | W 마른 우물 | (406, 114) |

- 수납장의 "북쪽"과 "남쪽"은 건물을 돌리기 전의 방향이고(구역 정의에서 문이 난 벽을 적는 방식과 같다), 수납장은 건물과 함께 회전한다. 한 집의 두 수납장을 다른 벽에 멀리 둔 것은 한자리에서 둘이 함께 잡히지 않게 하려는 것이다. 폐가 A의 가운데(지하의 대피소 입구 자리)는 비워 둔다.
- 차량 행렬의 두 트렁크 중 도입부에서 내용물이 고정되는 쪽(4.2)은 **둘째 차량의 트렁크**(`car_line_second_trunk`)다. 시작 지점에서 걸어오면 둘째 차량에 먼저 닿고, 그 트렁크는 두 차량 사이에 있다.
- 차량은 모델의 크기를 따라 길이가 6.1~6.7m다(개발 계획 2.30). 야외 상자는 차량의 앞뒤를 막지 않게 옆에 둔다.
- 차량의 뒤는 돌리기 전 기준으로 북쪽 끝이다(모델에서 브레이크등이 있는 쪽). 그래서 차량 행렬에서는 둘째 차량의 트렁크가 두 차량 사이에, 첫째 차량의 트렁크가 북쪽 끝에 있다.
- 흩뿌리는 바위는 상자 둘레를 피한다.

### 5.3 거리

이동 속도 12 m/s 기준이다. 속도를 올리면서 거리를 같은 비율로 늘렸으므로 걸리는 시간은 처음 설계와 같다.

| 구간 | 거리 | 걸리는 시간 |
|---|---|---|
| 시작 지점 → 차량 행렬 | 129m | 11초 |
| 차량 행렬 → 폐가 A | 230m | 19초 |
| 폐가 A → 폐가 B | 292m | 24초 |
| 폐가 A → 폐가 C | 212m | 18초 |
| 폐가 A → 야영지 흔적 | 151m | 13초 |
| 뒤집힌 차량 → 폐가 C (가장 가까운 대피처) | 174m | 14초 |
| 구역 끝에서 끝 | 720m | 60초 |

**예고 30초 기준으로, 상자가 있는 장소에서는 어디서든 12~17초면 대피처에 닿는다.** 남는 시간은 13~18초로, 상자 하나를 더 열 수 있을지 말지의 여유다. 폭풍을 맞으며 25초를 더 버틸 수 있으므로 판단이 조금 늦어도 바로 죽지는 않지만 체력을 잃는다.

구역의 모서리처럼 건물에서 먼 곳에서는 30초 안에 닿지 못한다. 플레이해 보고 너무 빠듯하면 예고를 늘린다.

| 항목 | 규칙 |
|---|---|

| 안내 | 단계마다 한 줄. 빠른 사용 칸 위에 나오고 단계가 바뀔 때까지 남는다 |
| 빠른 사용 칸 안내 | 물병이나 붕대를 처음 갖게 됐고 빠른 사용 칸이 모두 비어 있으면 12초 동안 지정하는 법을 알려 준다(4.5). 대피 단계의 안내는 가리지 않는다 |
| 보호 | 도입부가 끝나지 않은 처음 2분 동안 체력이 30 아래로 내려가지 않는다. 이미 30 아래였으면 더 내려가지만 않는다 |
| 강조 | 대피와 덮개 단계에서는 폭풍이 없어도 나침반의 대피소 표시가 커지고 깜빡인다 |
| 첫 귀환 | 첫 정산 창에 수리 목표를 설명하는 한 줄이 붙는다 |
| 건너뛰기 | 도입부를 한 번 끝낸 기기에서는 타이틀의 START 아래에 "도입부 건너뛰기" 스위치가 생긴다(처음에는 꺼져 있다) |

- 단계와 보호는 순수 함수다(`gameplay/intro.ts`). 도입부는 보고 알려 줄 뿐, 플레이어를 막거나 옮기지 않는다.
- 도입부가 있으면 시점 조작 안내(처음에 한 번 뜨던 것)는 띄우지 않는다. 첫 안내가 같은 것을 말한다.

### 5.5 대피소 구역과 구역 전환 (2.16)

마른 강바닥과 대피소는 서로 다른 구역이고, 한 번에 한 구역만 올라가 있다(기술 설계서 9장). 배치와 수치는 초기값이다.

**대피소 구역**

| 항목 | 내용 |
|---|---|
| 크기 | 한 변 16m의 방 하나. 바닥은 평평하고 벽 높이는 3.5m. 벽과 천장은 임시 도형 |
| 실내 구역 | 구역 전체가 대피 영역이다(화면에 "대피 중"). 폭풍의 피해가 없고 밤에도 식지 않는다. 갈증은 그대로 준다 |
| 보이는 것 | 하늘, 폭풍의 벽, 모래 입자, 줄어든 시야가 없다. 빛은 시각과 상관없이 일정하다. 폭풍 경고와 시각 표시는 그대로 나온다(밖의 상황을 알아야 나갈 때를 정한다) |
| 소리 | 바람 소리는 건물 안과 같게 줄어든다 |
| 나가는 곳 | 남쪽 벽 가운데의 사다리(임시 도형). 들어오면 사다리에서 6m쯤 떨어진 방 안쪽에, 사다리를 등지고 북쪽을 보고 선다. 처음에는 사다리 바로 앞에 세웠는데, 캐릭터 뒤에 서는 카메라가 벽에 밀려 사다리에 가려져서 옮겼다 |
| 나침반 | 대피소 안에서는 대피소 표시를 숨긴다 |
| 내용물 | 북쪽 벽의 수리할 문(2.18, 2.1). 그 밖에는 없다 |

**드나들기**

| 항목 | 규칙 |
|---|---|
| 강바닥 쪽 입구 | 폐가 A의 바닥 가운데에 있는 덮개(임시 도형, 1.4 × 1.4m. 길을 막지 않는다). 지하실은 따로 만들지 않는다 |
| 조작 | 입구가 상호작용 대상일 때(3.5) **E를 한 번 누른다.** 밟기만 해서는 넘어가지 않는다. 폐가 A는 폭풍을 피하는 곳이기도 해서, 걸어 들어갔다가 뜻하지 않게 넘어가면 안 되기 때문이다 |
| 안내 | 강바닥에서는 `[E] 대피소로 내려가기`, 대피소에서는 `[E] 밖으로 나가기` |
| 전환 | 화면이 0.35초에 걸쳐 어두워지고 → 구역을 바꾸고 → 가는 구역의 이름을 보여 주며 다시 밝아진다. 모두 1.5초 안쪽이다. 그동안 조작은 받지 않고, 열려 있던 가방 창과 상자 패널은 닫힌다 |
| 도착하는 곳 | 구역 정의의 진입 지점(`entries`). 강바닥에서는 덮개에서 동쪽으로 1.5m, 문 쪽(동쪽)을 보고 선다. 덮개가 등 뒤에 있어 곧바로 다시 대상이 되지 않는다 |
| 시각과 날씨 | 전환 중에도, 대피소 안에서도 그대로 흐른다. 폭풍 중에 나가면 밖은 폭풍이다 |

**구역 상태**

- 구역을 떠나도 그 구역의 일은 남는다: 상자의 상태(열렸는지, 남은 물건)와 바닥에 놓인 더미(4.7). 돌아오면 그대로다.
- 구역마다 상태를 따로 든다(`world/zoneState.ts`). 떠날 때 더미를 월드에서 거둬 적어 두고, 돌아올 때 다시 놓는다. 상자의 상태는 2.14부터 게임이 들고 있었으므로 그대로 쓴다.
- 그만하기로 타이틀에 돌아가면 모든 구역의 상태를 처음으로 되돌리고, 시작한 구역으로 돌아간다.
- 구역을 바꾸는 일은 한 틱 안에서 끝낸다(화면이 가려진 동안). 두 구역이 쓰는 모델은 게임을 시작할 때 모두 받아 두므로 전환 중에 내려받는 것이 없다.

**이 단계에서 하지 않는 것**

- 쓰러진 뒤 대피소에서 다시 시작하는 것과 가방을 떨어뜨리는 것은 2.20에서 만들었다(2.4).
- 대피소에 들어왔을 때의 귀환 정산(체력 회복, 다음 날 아침)은 2.17에서 만들었다(2.3). 수리는 2.18이다.
- 개발용: 시작 조건 `?zone=shelter`(대피소에서 시작)와 개발 패널의 구역 항목(바로 옮기기)을 둔다.

## 6. 언어

| 항목 | 내용 |
|---|---|
| 지원 언어 | 영어, 한국어 |
| 처음 실행할 때 | 브라우저 언어가 한국어면 한국어, 그 외에는 영어 |
| 변경 | 설정 메뉴에서. 바꾸면 바로 적용 |

- 화면의 모든 글자는 코드에 직접 쓰지 않고 **문구 파일**(`en.json`, `ko.json`)에서 가져온다. 물건 이름과 장소 이름도 같다.
- 두 파일의 항목이 서로 빠짐없이 맞는지 자동으로 확인한다.
- 글자를 이미지에 넣지 않는다. 글꼴은 기기에 있는 것을 쓴다(내려받는 용량을 늘리지 않기 위해).
- 문구는 짧게 쓴다. 영어와 한국어의 길이 차이로 화면이 깨지지 않게 한다.

## 7. 설정 메뉴 (시제품 범위)

본편의 전체 설정 메뉴 계획은 [게임 기획서](01-게임기획서.md) 15장에 있다. 시제품에는 테스트하는 사람이 불편 없이 플레이하는 데 필요한 것만 넣는다.

| 분류 | 항목 | 선택지 | 기본값 |
|---|---|---|---|
| 조작 | 마우스 감도 | 슬라이더 | 중간 |
| 조작 | 상하 반전 | 켜기/끄기 | 끄기 |
| 소리 | 전체 음량 | 슬라이더 | 80% |
| 화면 | 그래픽 품질 | 낮음 / 높음 | 높음 |
| 화면 | 전체 화면 | 켜기/끄기 | 끄기 |
| 화면 | FPS 표시 | 켜기/끄기 | 끄기 |
| 기타 | 언어 | English / 한국어 | 브라우저 언어에 따름 |
| 기타 | 기본값으로 되돌리기 | 버튼 | — |

- **여는 방법**: Esc. 일시정지 화면이 뜨고, 거기서 설정으로 들어간다. 일시정지 화면에는 계속하기, 설정, 조작 방법 보기가 있다.
- **적용**: 바꾸는 즉시 적용한다. 따로 저장 버튼을 두지 않는다.
- **보관**: 브라우저에 저장한다. 시제품에는 게임 저장이 없지만 설정은 다음 접속 때도 유지된다.
- **조작 방법 보기**: 키 배치를 그림 한 장으로 보여 준다. 키 설정 변경은 시제품에 넣지 않는다.

## 9. 정해지지 않은 것

| 항목 | 정하는 시점 |
|---|---|
| 의견을 받을 설문 주소 | 배포 단계 (개발 계획 2.27) |
| 최소 사양을 확인할 기기가 있는지 | 개발 PC는 Intel Arc 내장 그래픽이다(성능 로그로 확인). 내장 그래픽 중에서는 성능이 좋은 편이라 최소 사양의 기준으로 삼기 어렵다. 더 낮은 사양의 기기는 아직 없고, 구하지 못하면 최소 사양의 성능 기준은 확인할 수 없는 목표로 남는다. 통합 확인(개발 계획 7장) 전까지 정한다 |
| 폭풍 예고 길이(30초)가 적당한지 | 직접 플레이 후. 빠듯하면 늘림 |
